## 四、接口一览（前后端约定）

| 方法 | 路径 | 要登录 | 作用 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 否 | 注册，返回去掉密码的用户对象 |
| POST | `/api/auth/login` | 否 | 登录，返回 `{ token, user, redirect }`，同时下发 `user` cookie |
| GET | `/api/auth/me` | 是 | 用 JWT 取当前用户 |
| GET | `/api/auth/check-login` | 否 | 读 cookie 判断是否已登录（给旧页面用） |
| GET | `/api/users/me` | 是 | 取当前用户资料 |
| GET | `/api/users/:id` | 是 | 按 id 取用户资料 |
| PUT | `/api/users/:id` | 是 | 改资料（可带 `avatar` 文件），只能改自己 |
| DELETE | `/api/users/:id` | 是 | 删账号（连带删该用户评论），只能删自己 |
| GET | `/api/comments` | 否 | 全部评论（带作者信息、图片、时间） |
| GET | `/api/comments/:targetId` | 否 | 按页面/目标取评论 |
| POST | `/api/comments` | 是 | 发评论，`multipart/form-data`，字段 `content` + 可选 `image` |
| DELETE | `/api/comments/:id` | 是 | 软删除（`status='deleted'`），只能删自己的 |
| POST | `/api/comments/:commentId/images` | 是 | 给已有评论补图 |

统一约定：失败返回 `{ error: '中文提示', details?: '细节' }`，HTTP 状态码表达语义（400 参数错、401 未登录、403 越权、404 不存在、500 服务端错误）。

## 五、数据表（3 张）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | id、username(唯一)、email(唯一)、password(bcrypt 哈希)、avatar、bio、created_at | 注册用户 |
| `comments` | id、content、authorId(→users.id)、targetId、image、status(active/deleted)、created_at | 评论，用 `status` 做软删除 |
| `commentimages` | id、commentId(→comments.id)、imageUrl、filename、mime_type、file_size、status | 一条评论可挂多张图 |

图片地址统一存**相对路径** `/uploads/xxx.jpg`，不写域名和端口；前端用 `/uploads/` 相对路径请求，开发时由 Vite 代理，上线后由 Nginx 或 Express 直接提供。

## 六、怎么启动

### 方式一：一条命令起两个进程（推荐）

```bash
cd 新代码
npm install          # 首次
npm run start        # 同时起 Vite(5173) 和 Express(3000)
```

浏览器打开 http://localhost:5173 。

### 方式二：分开起（方便单独看日志）

```bash
cd 新代码
npm run dev          # 前端 5173
npm run server       # 后端 3000（node --watch，改代码自动重启）
```

### 方式三：生产部署（单端口）

```bash
cd 新代码
npm run build        # 产物进 dist/
npm run server       # Express 会自动托管 dist/，直接访问 http://localhost:3000
```

`server/app.js` 里判断了 `dist/` 是否存在：存在就顺带当前端服务器，不存在就只提供接口。
这样上线只有一个端口、一个域名，也不用再配 CORS。

## 八、这次后端迁移改了什么（逐条对照）

| 文件 | 改动 | 原因 |
| --- | --- | --- |
| `package.json`（新增） | 把 express/sequelize/mysql2/bcrypt 等依赖写清楚，加 `dev`、`server`、`start` 脚本 | 旧项目**没有 package.json**，依赖版本不可复现，换台电脑就装不回来 |
| `app.js` | 删掉 `../HTML`、`../css文档`、`../JS文件`、`../img`、`../video` 五个静态目录 | 前端已经由 Vite 打包，后端不该再管页面 |
| `app.js` | 新增 dist 托管 + SPA 路由回退 | 生产环境单端口部署，免 CORS |
| `app.js` | CORS 白名单 5500/5501 → 5173/4173 | 前端从 Live Server 换成 Vite |
| `app.js` | `.env` 按 `__dirname` 读；先连库再监听 | 换目录启动也能读到配置；避免端口起来但库没连上的假活状态 |
| `app.js` | 全局错误处理补上 multer 的 413 | 上传超限时给出明确提示而不是 500 |
| `routes/auth.js` | 响应和 Cookie 里去掉 `password` | 旧代码把 bcrypt 哈希直接返回给前端，属于信息泄露 |
| `routes/auth.js` | 默认头像 `/img/图标文件/默认头像.png` → `/uploads/default_avatar.png` | 旧路径指向的文件根本不存在，新用户头像必裂 |
| `routes/auth.js` | `redirect` 从旧页面路径改成 `/` | 旧路径在新工程里不存在 |
| `routes/comments.js` | 图片地址 `http://localhost:3000/uploads/x` → `/uploads/x` | 换域名后历史图片会全部 404 |
| `routes/userRoutes.js` | `GET /me` 挪到 `GET /:id` 前面 | 旧代码里 `/me` 被 `/:id` 抢先匹配，这个接口其实是坏的 |
| `routes/userRoutes.js` + `userController.js` | 更新、删除前校验"是不是本人" | 旧代码任何人登录后都能改/删别人的账号 |
| `userController.js` | 新增 `getMe`；头像改存 `/uploads/x`；只更新传来的字段 | 补上缺失接口，避免 `undefined` 把原值覆盖成空 |
| `userController.js` | 删账号改成事务：先删评论图片、再删评论、最后删用户 | 旧代码删账号必定 500（外键约束拦住了） |
| `middlewares/upload.js` | 上传目录从 `'uploads/'` 改成绝对路径 | 旧写法依赖启动目录，从项目根启动会把文件存错地方 |
| `utils/publicUser.js`（新增） | 统一去掉 `password` | 一个地方处理，避免每个接口漏改 |

## 十、还没做的（按优先级）

1. **前端还差的页面**：个人信息、个人空间、变速器调试、静态展示页、内容页、地图；
2. **multer 1.x → 2.x**：`1.4.5-lts.2` 有公开的安全公告，接口基本兼容，升级后需回归一次上传；
3. **登录 Cookie**：目前仍是 `httpOnly:false`（为兼容旧页面），新前端只用 JWT，建议后续改成 `httpOnly + sameSite=lax`；
4. **登录限流**：`/api/auth/login` 没有频率限制，容易被撞库；
5. **密码强度**：后端只校验长度 ≥6，建议加复杂度或长度上限提示；
6. **生产 HTTPS 与反向代理**：上线时用 Nginx 终结 TLS，把 `/api`、`/uploads` 反代到 3000；
7. **旧代码的 `video/` 有 4.7 GB**：如果只是本地演示没问题，若要做仓库请移到对象存储。

## 十一、PC 自适应（1280 ~ 2560）

### 目标与结果

桌面端已适配，5 个页面 × 7 个宽度（1024 / 1152 / 1280 / 1440 / 1600 / 1920 / 2560）
**全部没有横向滚动条，也没有元素被裁切**（`scripts/layout-audit.mjs` 输出 `0 / 35`）。

### 断点约定

| 宽度 | 表现 |
| --- | --- |
| ≥ 1920 | 内容限宽并居中（首页 1080、讨论区 1100、计算器 1400、变速器大全 1400） |
| 1440 ~ 1919 | 默认样式 |
| 1280 ~ 1439 | 表格字号/内边距收紧、导航字号 17px |
| 1000 ~ 1279 | 导航 15.5px、表格列更窄，仍不横向滚动 |
| < 1000 | 横向滚动（`body { min-width: 1000px }`），手机端下一步再做 |

### 四个固定写法

1. 容器宽度：`width: min(设计宽度, xx vw)`，不写死 px；
2. 字号：`font-size: clamp(最小值, x vw, 最大值)`；
3. 表格：`<colgroup>` 按百分比分列 + `table-layout: fixed`（见 `views/CalculatorView.vue`）；
4. 背景与图片：`background-size: cover`、`img { max-width: 100% }`（写在 `assets/base.css`）。

### 改动落在哪

| 位置 | 内容 |
| --- | --- |
| `src/assets/base.css` | 全局基线：`min-width: 1000px`、`img max-width`、长单词换行、`scrollbar-gutter` |
| `components/NavBar.vue` | 导航从"逐项写死 100px + 左对齐"改成 flex 均分居中，两侧给 logo 和登录区留位 |
| `components/FooterBar.vue` | `.div1` 固定高度 + 浮动 → flex 两端布局，表格 left 归零 |
| `views/ForumView.vue` | 讨论区 80% → `min(1100px, 92vw)`；底部评论条 50% → 居中 `min(760px, 94vw)` |
| `views/CalculatorView.vue` | 1200px 固定表格 → 流体表格 + colgroup 百分比列；表头从 space-around → 与列同宽的 grid；字号 clamp |
| `views/ShifterView.vue` | `#header1` 80% → `min(1400px, 92vw)`；图片容器 800×400 → `min(800px,100%)`；品牌卡 flex 自适应 |
| `views/HomeView.vue` | 卡片 `auto-fit minmax(230px, 1fr)`，1280 以上一行 4 张 |
| `assets/legacy/*.css` | 背景 `background-size: cover`；v-html 内容（品牌表格/图片）加 `max-width: 100%` |

### 顺便修掉的全局样式泄漏

这些选择器原来没有限定作用域，会串到别的页面上：

1. `页脚.css` 的裸 `table { position: relative; left: 100px }` → 装配清单整张表右移 100px，宽屏直接顶出横向滚动条；
2. `变速器大全.css` 的 `#header1 th, td`、`.series-section th, td`、裸 `th`、裸 `tr:hover` → 会把页脚和计算器的表格边框/悬停色一起改掉；
3. `@keyframes a { form { ... } }` 的 `from` 笔误（下载图标放大动画从来没生效过）。

### 怎么复检

```bash
npm run dev
node scripts/layout-audit.mjs                                   # 开发服务器
BASE_URL=http://localhost:4173 node scripts/layout-audit.mjs      # 构建产物（先 npm run build + npm run preview）
```

脚本会用 headless Edge 逐个宽度打开页面，输出每个组合是否正常，最后给出问题总数。
想顺便存图：加 `SHOT_DIR=$env:TEMP\shots`。

### 手机端后续建议（下一步）

1. 新增 `@media (max-width: 768px)` / `(max-width: 480px)` 两档，把 `body { min-width }` 去掉；
2. 导航改成汉堡菜单（抽屉），logo 与登录按钮留在顶栏；
3. 装配清单的表格在手机上不适合横向滚动，建议改成「卡片式一行一配件」；
4. 变速器大全的品牌卡从 flex 换行改成横向可滚动的小标签；
5. 讨论区的底部评论条改成 `position: sticky` 或直接放进页面流，避免遮住键盘。
